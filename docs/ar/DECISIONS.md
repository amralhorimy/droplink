# قرارات التصميم (ال«لماذا»)

[English](../en/DECISIONS.md) · [العودة إلى README](../../README.ar.md)

الكود الجيد يشرح *ماذا*. وهذا الملف يشرح *لماذا*، وما الذي ستفعله بشكل مختلف في الإنتاج.

### 1. الملفات تتجاوز الـ API
**القرار:** العملاء يرفعون وينزّلون من MinIO بروابط موقّعة.
**السبب:** يبقى الـ API صغيراً وسريعاً؛ رفع 100 ميغابايت لا يشغل worker ولا ذاكرة. يُوقَّع الرابط باسم المضيف **العام** لـ MinIO لأن التوقيع يشمل المضيف.
**المقابل:** يجب أن يصل العملاء إلى MinIO. في الإنتاج ضعه خلف نطاق خاص وTLS (`DROPLINK_MINIO_PUBLIC_ENDPOINT`).

### 2. POST policy بدل presigned PUT
**القرار:** الرفع عبر *نموذج* موقّع (POST policy).
**السبب:** الـ presigned PUT لا يستطيع تحديد الحجم. أما POST policy فتجعل MinIO نفسه يرفض أي شيء خارج `1…الحجم_المُعلَن` بايت أو أي مفتاح كائن آخر.

### 3. لا حسابات مستخدمين — `manage_token` سرّي
**القرار:** إنشاء الملف يعيد توكناً عشوائياً (يظهر مرة واحدة)، ونحفظ بصمة SHA-256 له فقط.
**السبب:** يُبقي المشروع مركّزاً على البنية التحتية، والتوكن كافٍ لعرض مفهوم التفويض. والمقارنة بزمن ثابت.
**في الإنتاج:** أضف مصادقة حقيقية (OAuth/JWT) واربط الملفات بالمستخدمين.

### 4. Redis Lua لعدّ التنزيلات
**القرار:** سكربت Lua واحد يفحص الحدّ ويزيد العدّاد.
**السبب:** «اقرأ ← قارن ← اكتب» سباق تزامن. مع 200 طلب متزامن يمرّر الكثير من التنزيلات الزائدة. سكربت Lua خطوة واحدة غير قابلة للتجزئة. أثبتها بنفسك: `make race`.
**الإصلاح الذاتي:** إن فقد Redis المفتاح (إعادة تشغيل بلا persistence أو إخلاء) يعيد السكربت زرعه من العدد المحفوظ في Mongo. كما يعمل Redis في compose مع AOF.
**ثغرة معروفة:** التنزيل «يُستهلك» عند إصدار التحويل لا عند اكتمال البايتات. وهذه المفاضلة المعتادة للروابط الموقّعة.

### 5. طابور على قوائم Redis (لا Celery ولا Streams)
**القرار:** `LPUSH` + `BLMOVE` + `LREM`، مع استرجاع عند الإقلاع.
**السبب:** يُقرأ في 40 سطراً، فيستطيع المبتدئ أن *يرى* كيف يعمل الطابور. يعطي توصيلاً «مرة واحدة على الأقل»؛ والمعالجات idempotent (آلة الحالات + مخرجات حتمية).
**الحدّ:** الاسترجاع يفترض عاملاً حياً واحداً لكل `WORKER_ID`. لعدة عمال استخدم Redis Streams مع consumer groups أو broker مخصصاً.

### 6. Pub/Sub للحالة اللحظية
**القرار:** العمال يعملون `PUBLISH` ونقطة SSE تعمل `SUBSCRIBE`.
**السبب:** تحديثات فورية بلا polling. والـ Pub/Sub «أطلق وانسَ»، لذلك **تشترك النقطة أولاً ثم تقرأ الحالة الحالية** — فيحصل العميل المتأخر على الحقيقة.
**الحدّ:** `EventSource` في المتصفحات لا يرسل ترويسات، فالبث يحتاج `X-Manage-Token`؛ استخدم `fetch()` streaming أو «تذكرة بث» قصيرة العمر في واجهة حقيقية.

### 7. صورة واحدة بثلاثة أدوار
**القرار:** الـ API والـ processor والـ janitor يشتركون في صورة Docker وكود واحدين؛ الأمر فقط يختلف.
**السبب:** بناء واحد، وتبعيات واحدة، ونماذج مشتركة. وسّع كل دور على حدة بـ `docker compose up --scale processor=3` (وأعطِ كل نسخة `DROPLINK_WORKER_ID` فريداً عند ذلك).

### 8. `platform/` مقابل `modules/`
**القرار:** أغلفة البنية التحتية (ولكلٍّ `errors.py` خاص) منفصلة عن ميزات العمل.
**السبب:** استبدال MinIO بـ S3 أو Mongo بـ Postgres يلمس مجلداً واحداً. وقواعد العمل تبقى مقروءة لأن استثناءات الدرايفر لا تتسرّب إليها.

### 9. نظام أخطاء مركزي بمسارين
**القرار:** كل خطأ هو `AppError`؛ ومعالج واحد يسجّل التفاصيل ويرجع غلافاً آمناً.
**السبب:** المطوّر يحصل على السياق كاملاً و`request_id`؛ والمستخدم لا يرى الداخل أبداً. وقيم `code` الثابتة عقد يعتمد عليه العملاء.

### 10. فهرس TTL في Mongo للتنظيف
**القرار:** حذف الملف يضع على السجل `deleted` ويحدد `purge_at`؛ وفهرس TTL يزيل السجل لاحقاً.
**السبب:** نافذة تدقيق قصيرة، وبلا كود تنظيف للخطوة الأخيرة.

### 11. تحديد معدل بنافذة ثابتة
**القرار:** `INCR` + `EXPIRE` في Lua لكل IP.
**السبب:** بسيط ورخيص. **الحدّ:** اندفاعات عند حافة النافذة. في الإنتاج فكّر في نافذة منزلقة أو token bucket، وحدّد المعدل عند CDN أيضاً. وNginx يضيف طبقة ثانية أخشن.

### 12. scrypt من المكتبة القياسية
**القرار:** كلمات مرور الروابط تُجزَّأ بـ `hashlib.scrypt` وتُنفَّذ في thread (`asyncio.to_thread`).
**السبب:** لا تبعية إضافية، ومكلفة للذاكرة عمداً، والـ thread يُبقي الـ event loop متجاوباً. ومحاولات كلمة المرور محدودة لكل رابط وIP.

### 13. ما سيضيفه إصدار إنتاجي
مصادقة وحصص · فحص فيروسات في الـ processor · قواعد lifecycle في التخزين كشبكة أمان ثانية · مقاييس وتتبّع (Prometheus، OpenTelemetry) · استراتيجية migrations · Redis/Mongo مُدارة بنسخ احتياطي · TLS في كل مكان.
